# Stayplaytion Desktop — Stage 6.6A–6.6D

**Статус:** постоянный Desktop и мост для нативных framebuffer-приложений реализованы в development branch. Это описание не означает, что все приложения и сценарии уже прошли окончательную аппаратную приёмку.

Исходники и workflow: [ветка разработки](https://github.com/irman100/H3531/tree/feature/h3531-stage68-desktop-input-polish/ports/stage66a).

## Зачем менялась архитектура

Ранняя система работала по модели «Monitor запускает одно полноэкранное приложение, после выхода запускается Monitor». Это хорошо подходило для первых тестов, но не позволяло использовать устройство как обычный компьютер.

Stage 6.6 перевёл систему на постоянную X11/LXDE-сессию. Обычные окна не должны завершать Desktop, а старые программы с прямым доступом к /dev/fb0 должны получать экран через контролируемую временную аренду.

## Desktop

Базовая цепочка:

- h3531-session и supervisor;
- краткая совместимая инициализация HDMI/HIFB штатным Monitor;
- автоматическое поднятие Ethernet/DHCP;
- Xfbdev;
- Openbox;
- PCManFM;
- LXPanel.

FBZX по умолчанию может открываться как X11-приложение. Закрытие окна не должно завершать X-сессию, закрывать папки или перезапускать панель.

## Этапы приложения и framebuffer

| Этап | Назначение |
|---|---|
| 6.6A | Постоянная LXDE-сессия, сеть и запуск FBZX в окне |
| 6.6B | APPINFO.CFG: манифесты, тип backend и файловые ассоциации |
| 6.6C | Первый Native App Bridge для приложений, которым нужен прямой framebuffer |
| 6.6D | Live framebuffer lease: Desktop остаётся живым, а владение framebuffer и input временно передаётся нативному приложению |

Live lease сохраняет состояние framebuffer и alpha, приостанавливает только копирование Xfbdev-shadow в физический экран, отключает конкурирующий XInput, запускает одно native-fb приложение, затем восстанавливает экран и input и инициирует перерисовку Desktop.

## Безопасность

- Не используется saveenv.
- Экспериментальные образы не записываются в SPI NOR.
- Заводской U-Boot не заменяется.
- Monitor остаётся совместимым fallback/rescue-компонентом.
- Прямой framebuffer должен иметь одного владельца в каждый момент времени.

## Что проверять на устройстве

1. Холодная загрузка до постоянного Desktop.
2. Автоматическая сеть/DHCP.
3. Открытие и закрытие FBZX как обычного окна без перезапуска LXDE.
4. Запуск native-fb приложения через bridge.
5. Возврат из native app с восстановленным framebuffer, alpha, input и Desktop.
6. Подключение/отключение USB-клавиатуры, мыши и накопителя.

Публичный USB Kit v0.7 не содержит весь этот поздний Desktop-стек. Он находится в development branch и должен рассматриваться отдельно от опубликованного v0.7 demo.

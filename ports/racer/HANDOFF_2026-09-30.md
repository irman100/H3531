## CRITICAL importer discovery: IPL transform was wrong

Comparison with reVC `CFileLoader::LoadObjectInstance` showed our world placement was wrong in two ways:

1. reVC uses IPL quaternion as axis + negative angle:
   `angle = -2*acos(w)`.
2. reVC reads IPL scale but does not apply that scale to the object instance matrix.

Our importer previously used the opposite quaternion rotation and multiplied instance geometry by IPL scale.

### Already changed in current branch AFTER Stage8.8b package

`ports/racer/vc_local_import.py` now has reVC-compatible helpers:
- `qrot_vc_ipl(...)`
- `transform_vc_instance_point(...)`

The same transform is used for visual DFF and COL.

A placement selftest was added.

### Consequence

The user's current VCMAP.BIN and VCCOL.BIN were generated with the old transform.

They MUST be regenerated together before judging object placement, bridge placement or suspension contact again.

### Where spawn actually lives

Spawn is embedded directly in the VCMAP3 header:

```text
0x00 magic "VCM3"
0x04 version
0x08 world_scale
0x0C sector_m
0x10 spawn_x
0x14 spawn_y
0x18 spawn_z
0x1C spawn_yaw
```

Importer format:
`<4sI10f6I`

The header stores unscaled map coordinates; runtime multiplies them by world_scale (240).

Example:
- importer ~599.39, 13.41, -234.52
- runtime ~143853, 3219, -56285

Next useful tool:
`vc_spawn_patch.py` with:
- show VCMAP.BIN
- set-world X Y Z [yaw]
- set-gta X Y Z [yaw]

This would change only the four floats and avoid rebuilding the map.

Later, a real runtime control channel should use writable `/var`, not `/tmp`.
